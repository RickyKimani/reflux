# Benchmarks

Generated by `v run tools/benchmarks.vsh` from `testdata/m3_bench.json`, which `tools/gen_m3_bench.py` writes (M3 step 10, decision D10, exit criterion 8), and `testdata/m4_bench.json`, which `tools/gen_m4_bench.py` writes (M4 step 9, D14, criterion 9). Don't edit this file by hand. The flashes come first, and [the reference flowsheet](#the-reference-flowsheet) after them.

**What is timed.**
- **The flashes:** PT with two phases and with one, PH, and the bubble point at a given P, for a 2-, a 5- and a 10-component mixture. All three programs use Peng–Robinson with DWSIM's constants and kᵢⱼ.
- **The states:** each case is 40 nearby states, so nothing is merely repeated: PT and PH at T₀ + 0.05 K·k, the bubble point at P₀·(1 + 0.001·k). PH is by state: each program computes its own H at the PT state, untimed, and its PH flash from that H is timed.
- **The timing:** every flash on its own, after one untimed pass over the states, warm, in one process per program. The tables give the median.
- **Case by case:** on this laptop the same flash's median moves by up to 3× from one session to another, with its power state, so the three programs time each case one straight after the other, within seconds. Timed minutes apart, the ratios moved by 2×.
- **The programs:**
  - reflux at its default tolerances (|ln fᵢⱽ − ln fᵢᴸ| ≤ 1e-12, every split verified), built with gcc 16.2.0 -prod;
  - thermo 0.6.1's FlashVL at its default tolerances, from Python 3.13.17;
  - DWSIM 9.0.5.0's "Peng-Robinson (PR)" package, called directly through pythonnet 3.0.5, at its default PT and PH tolerances and at 1e-8.

**The machine:** AMD Ryzen 5 PRO 3500U w/ Radeon Vega Mobile Gfx, Windows-11-10.0.26300-SP0, on 2026-11-03, with V eab77e7.

## The reference flowsheet

M4 step 9, decision D14, exit criterion 9: `testdata/flowsheets/reference_dwsim.toml`, the reference flowsheet on DWSIM's constants and kᵢⱼ, solved in each program. `tools/gen_m4_bench.py` writes `testdata/m4_bench.json`, timing DWSIM and then reflux within the same minute, on AMD Ryzen 5 PRO 3500U w/ Radeon Vega Mobile Gfx, Windows-11-10.0.26300-SP0, on 2026-11-03.

- **A first solve** is of a flowsheet just built: loaded from its file in reflux, built through the automation in DWSIM, after one untimed first solve so that .NET has compiled it.
- **A solve again** follows the feed 0.01 K warmer each time. DWSIM starts it from its last answer. reflux has no warm start until M8 (F5), so its solve again is a first solve in a warm process.
- **reflux** at its default tolerance, 1e-9 of each tear variable's scale, by Wegstein (its default) and by direct substitution, built with gcc 16.2.0 -prod. Its load is the file, the component data and the fluid.
- **DWSIM 9.0.5.0** at its default recycle tolerances, and at them scaled by 1e-8, which closes the balances to its floor (step 0). Its acceleration changes nothing here, so it's off: in effect DWSIM's recycle is direct substitution.
